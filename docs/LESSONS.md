# Executable lessons

Open these from the Atlas menu, or use their hash routes. Numerical labels are optional in the tensor, tile and encoder–decoder scenes.

| Route | Computation | Executable PyTorch counterpart |
| --- | --- | --- |
| `#tensor-ops` | Shapes, strides, shared storage, copying, head layouts and contraction | `reference/tensor_ops.py` |
| `#training` | An isolated next-token training step, parameter gradients and consecutive SGD/AdamW updates | `reference/training_lesson.py`, using `reference/model.py` |
| `#flash` | Stable tiled attention for the main model’s selected layer/head/query | `reference/flash_attention.py` |
| `#encoder-decoder` | One complete encoder and decoder with rectangular cross-attention | `reference/encoder_decoder.py`, reusing modules from `reference/model.py` |
| `#architectures` | Structural recipes, equations and optional unique parameter counts | The training profiles and encoder–decoder class above |
| `#exercises` | Sixteen shape, debugging, derivation and coding tasks | Each task links its relevant operation and maths |

The main model is unchanged by the training and encoder–decoder lessons. Both use seeded, untrained miniature models, rather than interpreting their distributions as language or translation quality. The architecture cards disclose vocabulary, FFN and topology differences; their counts are illustrative, not a controlled efficiency comparison.

Training uses three supervised positions in the four-token input `cat.`. The last position has zero **logit** gradient, while tied vocabulary weights accumulate both lookup and output-head contributions. SGD has no decay; AdamW decays matrices but excludes norm/bias vectors. Consecutive updates retain actual moment state and bias correction.

The encoder–decoder follows 2017 conventions: post-LayerNorm, sinusoidal positions, √d embedding scaling, ReLU, shared vocabulary embeddings and three decoder sub-layers. Dropout is disabled. Source padding is excluded as a key in encoder and cross-attention; target padding is excluded as a decoder key. Padded query rows are computed, so a downstream training objective would also need to ignore padded targets.

FlashAttention uses an **unnormalized** accumulator U and running maximum/normalizer. It verifies the final output against the live dense trace; a selected intermediate tile shows only a prefix output. HBM/SRAM labels describe the GPU algorithm’s memory roles. The browser retains dense tensors and snapshots for teaching and validation: it is a CPU recurrence demonstration, not a fused GPU kernel or benchmark.

Coding tasks use synchronous JavaScript functions in disposable workers. Timeout, cancellation and navigation terminate the worker and release its blob URL. They do not run Python or access the main model; a worker is not a security sandbox. Worked derivations are educational solutions, not automated proof checking. Progress includes practice after revealing solutions, is labeled “practiced,” and stays in browser-local storage.

## Verification

Run computation-heavy checks on a compute node under the contributor guide’s cluster rules:

```bash
node tests/tensor-ops.mjs
node tests/training.mjs
node tests/flash.mjs
node tests/encoder-decoder.mjs
node tests/exercises.mjs
node tests/math.mjs
node tools/gen_codemap.mjs --check
```

The corresponding `tools/export_tensor_ops.py`, `tools/export_training.py`, `tools/export_flash.py` and `tools/export_encdec.py` regenerate independent PyTorch fixtures. Training and encoder–decoder export scripts consume weights generated by their `*_inputs.mjs` scripts. Lesson fixtures live below `tests/fixtures/lessons/`, leaving the main-engine fixture suite separate.

Browser checks always use `tools/smoke.sh`. Each lesson has a `tests/browser_*.js` interaction check; source-routing regression coverage lives in `tests/browser_reference.js`. Also check the standalone build and inspect desktop/mobile screenshots in both themes.
